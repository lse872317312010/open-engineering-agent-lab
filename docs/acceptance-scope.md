# 验收范围：仿真优先，真机由用户负责

生效日期：2026-10-23（Asia/Shanghai）。来源：用户明确要求
“只要在仿真环境里能完成就算 OK，不必上真机，真机这块我自己来”。

## 执行约束

- Agent 的交付与阶段验收以可重复的模型仿真、独立指标、SIL、静态检查及适用的离线构建为准。
- 已声明的功能在仿真环境达到固定验收指标，即可完成对应交付并继续后续开发。
- 真机适配、刷机、上电、板端 PIL/HIL、真实电机测试、实测时延和资源由用户负责；
  缺少板卡、实际固件、板端日志或厂商工具链不阻塞仿真范围的推进。
- 平台/型号专用构建按工具链可用性记录已验证或未验证，不把未运行目标标记为已支持。
- 继续按独立测试检查误差、时序语义、边界条件和复现性，保留输入、版本、容差和结果。
- 报告明确功能范围；PI 内核通过不自动表示完整 FOC 固件通过。
- 仿真和 SIL 证据保留 model_simulated / SIL_passed 等真实等级。
  PIL_measured、HIL_measured、physical_measured 仅用于实际测量，仿真不能替代这些标签。

## P5 的新完成条件

P5 调整为“目标相关仿真验证与硬件交接包”：
已声明控制内核的仿真/SIL 在固定容差下通过；提供源码、接口/单位/状态更新顺序、
共享向量、可复现命令、验证报告、已完成构建的产物，以及由用户接手的硬件事项。
板端时间、实际 Flash/RAM/栈和 MCU PIL 退出本轮 Agent Gate。

既有运行报告中的 p5_gate_passed=false 表示旧版真机 Gate 未运行/未通过；
保留历史原始报告。新版仿真交付状态在 docs/stage-status.md 中单独说明，
不改写过去的测量事实。本约束替代此前文档把真机结果设为 Agent 开发前置条件的条款。

## ARM / RISC-V 处理器集成仿真

用户于 2026-10-23 进一步允许以 ARM 或 RISC-V 环境集成仿真完成 PIL-style 验证，
由 Agent 选择后端。本轮采用 QEMU ARM Cortex-M4，见 [processor-emulation.md](processor-emulation.md)。
处理器仿真报告标记 processor_emulated，保留 ELF、原始回传与独立比对结果；
该验证可用于仿真 Gate，不要求真机，不标记为 PIL_measured。
