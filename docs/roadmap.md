# 开发路线图（Roadmap v1.2）

> 项目：Open Engineering Agent Lab（OEAL）  
> 更新日期：2026-10-26  
> 定位：开放、可迁移、可验证的 **Python + AI Agent 原生工程建模与自主研发平台**。  
> 第一垂直领域：PMSM / FOC / 机器人关节伺服。  
> 核心资产：模型、代码、实验数据、工程知识、验证证据；不绑定 MATLAB、单一 LLM、求解器或 MCU 厂商。

## 验收范围约束

用户于 2026-10-23 明确：仿真环境能完成即可，真机由用户负责。
Agent 按仿真、独立验收和 SIL 推进；板卡、刷机、PIL/HIL 与实测资源不作为开发完成前置条件。
详见 [acceptance-scope.md](acceptance-scope.md)，证据等级仍按真实来源记录。

## 0. 计划新增前的基线与事实边界

以下为本路线图首次制定时的基线；本轮实现的实际状态见末尾实施状态。

计划制定时远程仓库已有：
- Python 包 `oeal`；固定步长 RK4 PMSM dq 电气与机械模型；
- JSON 工况、`oeal simulate` CLI、CSV 轨迹与 JSON 摘要；
- 数值/CLI 测试和 Python 3.10–3.12 GitHub Actions CI 配置；
- `docs/model-contract.md` 中的坐标、方程、假设和适用范围。

**这些是仓库已有实现，不代表本路线图新增了功能。** 本文档更新没有进行真机测试，也不凭 CI 配置文件的存在宣称所有远程 CI 已通过。该历史基线采用平均电压假设；之后接入的 FOC、开关与机器人模型见阶段状态和项目架构。

## 3. P1：项目研究与 PMSM-FOC 可验证基准（近期主线）

### P1-A 开源项目技术选型

逐一记录上游版本/commit、许可、Python 支持、维护活跃度、可编程 API、求解器精度、事件与多采样率语义、性能、数据格式、执行安全性、可替换性。

首批候选：
- PathSim / PathView：通用系统仿真、可视化和模型交换；
- motulator：电机/逆变器/控制器领域参考；
- Agentic Embedded Lab：实验调度、证据管理和 Agent 工具接口；
- Mavrith：Agent 可检查的模型表示；
- OpenModelica/FMI：后期多物理场互操作；
- SemaPLC：Agent 代码编译—运行—验证工作流参考。

**禁止仅凭 README 宣称支持就直接采用。** 每个候选必须做 `adopt / adapt / reference-only / reject` 决策和可重复实验；不得在未核验许可证前复制代码。详细实施见 [P1 评测执行计划](p1-evaluation-plan.md)。

### P1-B 电流环闭环基准

在现有 `oeal` 模型之上，优先增加：
1. 电机参数与单位验证；Clarke/Park 变换及数学参考测试。
2. 20 kHz 离散 dq PI（限幅、抗积分饱和、解耦/反电势补偿），定义积分和状态更新顺序。
3. 平均电压 SVPWM 线性区近似及母线电压约束；先不宣称开关级精度。
4. 独立 RL 解析极限、阶跃、饱和、参数偏差、固定步长收敛测试。
5. 建立 PWM/ADC 更新顺序和延迟的**明确语义接口**，后续逐步引入真实开关与中断事件。

参考工况：电流环 `Ts=50 µs`，`i_d_ref=0`，`i_q_ref: 0→5 A`；具体电机参数只用经注明来源的研究示例，不能冒充实测参数。

**Gate P1：** 开源评测报告 + 选择记录（ADR）；FOC 测试自动运行、输出指标可重算、数值基准有独立参考。

## 4. P2：统一模型中间表示（Model IR）

规划对象：
- `ModelSpec`：参数、单位、状态、端口、动力学方程引用、采样/事件时钟及适用域；
- `ExperimentSpec`：工况、模型版本、求解器设置、种子、预算、验收约束；
- `SimulationResult`：信号、单位、时间基准、指标与执行元数据；
- `CodeArtifact`：目标 MCU/ABI、编译器、配置、源码版本及资源预算；
- `Evidence`：来源、环境、命令、结果、容差、证据等级与不可变引用。

交付顺序：v0.1 JSON Schema → 单位/范围/采样率校验 → 往返测试 → 对接现有 CLI → 至少一个外部后端适配器。**IR 是平台长期资产，PathView JSON/Modelica 不应成为唯一事实源。**

## 5. P3：AI Agent 自主研发

Agent 只负责提出假设、修改工程文件、选择试验和解释失败；仿真、指标计算、验收标准与证据存储由独立工具实现。

首版工具（拟议）：`inspect_model`、`run_experiment`、`compare_results`、`propose_change`、`verify_change`、`record_evidence`。

- 本地优先，LLM/Agent 框架可更换，仿真不依赖 AI 服务在线；
- 限制任意代码执行；对 Agent 生成的脚本采用隔离环境和权限边界；
- Golden 验收集由独立测试维护，Agent 无权在同次优化中重定义达标标准；
- 每次改动保留 Git 版本、输入、输出、模型/代码散列及失败原因。

**Gate P3：** 给定固定要求，Agent 能重复完成至少一个“建模/整定→仿真→验收→修复→报告”的受控闭环；对未通过的需求明确报告失败。

## 6. P4：C/Rust 实现与 SIL

不优先自研完整 Simulink 式图形化代码生成器：由 Agent 按规范编写 C（首选，便于 STM32/C2000 现有固件复用），Rust 作为可选目标。

- 明确离散状态转移函数：输入采样、输出限幅、积分更新次序、延迟和初始化；
- 用**独立定义**的共享测试向量对比 Python↔C/Rust；
- 处理浮点精度、固定点溢出、NaN/Inf、饱和与参数极值；
- 编译/静态检查与功能测试纳入 CI；禁止用修改黄金数据掩盖失配。

**Gate P4：** SIL 报告记录逐样本误差、失败向量、容差理由、编译工具链与源码散列；还不能声称已满足目标硬实时性。

## 7. P5：目标相关仿真验证与用户交接

依据 2026-10-23 用户约束，Agent 在仿真环境完成交付，用户接手真机工作。
目标顺序仍为 STM32G474 Cortex-M4F → TI C2000，按可用工具链记录离线构建覆盖。

- 在仿真/SIL 中验证声明的控制状态转移、浮点误差、限幅和异常行为。
- 提供源码、ABI/单位、初始化/更新顺序、共享向量、运行命令和结果散列。
- 有工具链时生成交叉编译、对象 size/反汇编和静态检查报告；明确其适用范围。
- 真实 HAL/ADC/PWM/DMA/编码器集成、刷机、板端时间/抖动/资源和 PIL/HIL 由用户负责，
  无相应硬件或日志不阻塞 Agent 的仿真阶段。
- 主机执行时间、仿真周期和对象大小各按原始含义报告，保留实际证据等级。

**Gate P5（仿真范围）：** 声明功能通过固定仿真/SIL 指标，交接包可复现并列明硬件待办。
真机 PIL/实时性与资源实测由用户独立验收，不作为本 Gate 的前置条件。

## 8. P6：多物理与真实数据

从“平均电压 PMSM + 电流环”逐步增加：
1. 逆变器死区/调制/母线纹波、PWM/ADC 同步与保护事件；
2. 减速器摩擦、弹性、传动误差、惯量与双编码器；
3. MOS / PCB / 绕组 / 壳体热阻-热容网络；
4. 使用 OpenModelica、FMU 或其他后端联合仿真；
5. 利用经过授权的实测日志进行参数辨识，并严格区分训练/标定集和独立验证集。

**Gate P6（仿真范围）：** 数值一致性、仿真性能、不确定度与模型适用边界有可复现报告。
缺少实测数据时明确采用合成/示例参数；用户提供真实数据后可追加标定与独立验证，
真机采集和实测误差验收由用户负责，不阻塞仿真交付。

## 9. 横向质量与治理要求

- **优先复用成熟开源能力。** 核心对外 API 可替换；许可证审查在引入依赖前完成。
- **模型即代码、证据即资产。** 必须能离线复现，输入/输出采用开放格式。
- **安全隔离。** Agent 不能直接修改或绕开独立验收标准，也不能在未经许可时操作真机。
- **测试不能证明零缺陷。** CI 绿灯不等于工业级可靠性、硬实时保证或功能安全认证。
- **分层评价。** 对标 Simulink 时区分求解精度、工程效率、许可证成本、集成/维护成本和验证成熟度。
- **避免无谓开发。** 不以重写求解器、拖拽 GUI 或完整 Embedded Coder 为前置条件。

## 10. 当前工作队列（2026-10-26）

以下顺序按当前已合并能力推进；最初的 P1–P5 退出门槛保留在历史章节。

1. **已验证：能量端口与局部电驱—热闭合。** 额外器件热匹配实际直流支路，
   摩擦进入热网络，连续温度反馈；用固定方程和独立极限验收。
   [能量契约](energy-accounting-contract.md)先于模型实现提交。
2. **已验证：机器人耦合误差改进。** 在已实现端口审计之上加入中点转矩预测、
   实际有效惯量、路径分段积分、因果位移权重、RK4 选项与未解决事件回退；同积分器、固定控制器下做
   200 / 100 / 50 μs 收敛及载荷/原长轨迹验证。不得把能量误差移作发热。
   [实现前契约](midpoint-coupling-contract.md)冻结至少 75% 峰值改善与原物理目标。
3. **长时、多工况与鲁棒性（推进中）。** 已新增[一小时热网络回放验收](thermal-endurance-contract.md)，
   六组固定合成热场景已进入主线。PR #15 原九组 1–2 s PWM 留出保留，
   PR #16 改为逐工况执行，并补七组已知参数/PWM/传感器检查与离线报告；
   16 组及两组步长敏感性门槛已通过，六图交互报告与独立全量审计通过。
   固定门槛和实际运行结果见[秒级联合契约](joint-robustness-contract.md)及阶段状态。
   扩大轨迹、载荷、温度与参数范围；
   保留训练/验证/留出隔离，先选择求解精度和模型保真度，再扩大搜索预算。
4. **完整关节 FMI / OpenModelica 互操作。** 从当前单节点 RC 走向有明确
   能量端口与时钟语义的电驱/机械/热交换；开源 FMU 必须先核验版本、许可与数值行为。
5. **完整控制内核 SIL / ARM 仿真。** 从 PI 扩展到坐标变换、FOC 状态与保护顺序，
   不以真机资源或厂商 HAL 集成为前置条件。
6. **可替换在线 Agent 运行时。** 在已固定工具与验收边界内评测自然语言规划、
   失败诊断及预算控制；离线仿真与证据不依赖在线 AI 服务。

> 阶段名称与旧版对应关系：原“FOC 闭环”纳入 P1-B；原“关节与热模型”延后至 P6，实验记录契约前置到 P2/P3；原“Agent 实验助手”和“嵌入式对照”细化为 P3–P5。

## 14. 中点预测的退出条件

本轮从“发现接口误差”推进到有独立参考的模型预测与公平对照。
该方法不回滚真实子系统，也不是完整非线性隐式解；即使达到改善门槛，
机器人端口/积分求积余额仍保留。后续秒级、长时热与多工况验证继续独立推进。
固定验收和实际证据见[中点契约](midpoint-coupling-contract.md)与[阶段状态](stage-status.md)。

后续秒级验证仍需循环轨迹及控制器名义参数冻结后的未知参数失配检查；
本轮已知参数变体不替代这些实验。大规模原始流聚合需保留充分审计时间，
可继续评估独立并行审计，不能用未经重算的汇总代替 Gate。
